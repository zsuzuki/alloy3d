# Original crown billboards

These 24 transparent PNGs are rendered from this sample's own `crown*.glb` and `leaves*.glb`,
not generated by an image model or downloaded from an asset library. Each of the three trees
has eight orthographic horizontal views at 45-degree increments, at 768 by 768 pixels.
`frames.json` records the square frame size and vertical center in crown-local coordinates.
`manifest.json` records SHA-256 hashes of the six source GLBs and all 24 PNGs.

The scene keeps trunks in 3D and uses these cutout crown cards beyond 38 metres.
The nearest azimuth view is selected relative to the tree's rotation; the card faces the camera
around its vertical axis. Its two triangles carry the same crown placement and wind phase.
Lighting is baked, while scene fog is applied at runtime. Elevation parallax, continuously
changing lighting, and crossfades between views or detail levels are not represented.
The card casts an approximate cutout shadow. `I` toggles billboards for comparison.

## Regeneration

After changing tree geometry, generate the source models first, then bake on a Mac with Metal:

```sh
python3 tools/generate_forest_assets.py
cmake --build build --target alloy3d_forest_billboard_baker -j 8
python3 tools/generate_forest_billboards.py --bake build/tests/alloy3d_forest_billboard_baker --shaders build/shaders/shaders.metallib
cmake --build build --target alloy3d_forest -j 8
```

The baker target is available with `ALLOY3D_BUILD_TESTS=ON`. Ordinary builds use checked-in
images and GLBs and need no baking. Rebake after changing the sample's baked lighting or leaf shader too.

```sh
python3 tools/generate_forest_billboards.py --check
```

This check validates source/image hashes and the deterministic GLB packaging. It does not
promise pixel-identical rebaking across different GPUs or renderer versions.
