# 基本マテリアル

GLBの `alphaMode`、`alphaCutoff`、`doubleSided`、`KHR_materials_unlit` を読み取り、
通常描画・インスタンス描画・共有モデルの複製に反映します。
追加のAPI呼び出しは不要です。色付きの簡単なライティングを維持し、PBR計算は導入していません。

## 透明モード

| GLBの指定 | 表示 | 深度書き込み | 描画順 |
|---|---|---|---|
| OPAQUE（既定値） | 素材・頂点・画像のアルファを無視して不透明 | あり | 半透明より先 |
| MASK | 合成アルファがcutoff未満のピクセルを破棄 | 残ったピクセルのみ | 半透明より先 |
| BLEND | 背景と通常のアルファ合成 | なし | 不透明・切り抜きの後、奥から手前 |

MASKのcutoffは既定値0.5で、同値のピクセルは残します。
素材のbaseColorFactor、頂点カラー、baseColorTextureのアルファを掛けて判定します。
RGBは従来どおり、この3つの色と描画時の色指定を掛けます。

`DrawModel3D` / `ModelInstance::color` のアルファは、アプリ側のフェード指定として残しています。
GLBの透明ルールを処理した後に掛け、1未満なら半透明として描きます。
例えばOPAQUEのモデルも `color.w = 0.5f` でフェードできます。
MASKでは穴の判定を変えず、残った部分をフェードします。通常の色指定は各成分0〜1です。

半透明は**モデルのパーツ単位**で並べ替えます。同じ深度のパーツは登録順を保ちます。
交差する面や、一つのパーツ内部で前後が混在する形状について、完全な合成順は保証しません。
三角形単位のソートや順序に依存しない透明描画は、この実装の範囲外です。

モデル以外の線・基本図形は従来どおりモデルの前、3D文字はモデルの後に描きます。
それらの半透明とモデルの半透明をまとめてソートする処理はありません。

## 両面とライティング

`doubleSided` がfalse（既定値）の素材では裏面を表示しません。
trueなら裏面も描き、裏面では法線を反転してライティングします。
負のスケールによる反転は、ノード変換・スキニング・配置変換を含めて扱います。
反転した配置が一括描画に混在できるよう、モデルの表裏判定はフラグメント側で行います。
そのため裏面にもフラグメント処理のコストが発生します。

`KHR_materials_unlit` がある素材は、ライトの方向や強度に影響されず基本色を表示します。
テクスチャ、頂点色、透明モード、描画時の色指定は有効です。
指定のない素材には従来の環境光＋平行光源の簡単な拡散反射を使います。

## インスタンス描画と負荷

全パーツがOPAQUEまたはMASK、かつ全配置の色アルファが1以上なら、
テクスチャの有無によらず1パーツ1回のインスタンス描画を使います。
一つでもBLENDのパーツ、またはアルファ1未満の配置があれば、呼び出し全体を個別描画に戻します。
1パーツだけの半透明モデルも対象です。他のモデルと一緒に正しい前後順へ並べるためです。

ソート用の中心は、現在の姿勢を反映した保守的な境界から求めます。
ロード時に関節ごとの影響頂点の境界を作り、必要になったときだけ現在の行列で変換します。
頂点を毎フレーム走査せず、姿勢が変わらなければ計算結果を再利用します。
境界の定義は共有モデル間で共有し、変換後の中心は姿勢ごとに独立しています。
公開API `Model::GetBounds` の正確な頂点走査とは別の、ソート用の近似です。

半透明パーツ数をTとすると、並べ替えはO(T log T)、ソート用配列はO(T)です。
配列の容量はフレーム間で再利用し、`ReleaseUnusedMemory()` で空の配列の確保分を解放します。
これらのCPU領域は既存の頂点・インスタンスGPUバッファ統計には含みません。

## サンプルと回帰テスト

ビューワーの **M** でマテリアル展示を開閉します。
アルファの小さいOPAQUE、格子のMASK、赤青のBLEND、回転する片面／両面、Lit／Unlitを比較できます。
**F** の全体表示と **O** の投影切り替えも使えます。

`assets/tests/materials` のGLBは、すべてこのリポジトリ用に生成した単純な板モデルです。
次のコマンドで再生成・一致確認できます。

```sh
python3 tools/generate_material_fixtures.py
python3 tools/generate_material_fixtures.py --check
```

`material_regression` は小さなオフスクリーン画像を読み戻し、期待値と比較します。
透明モード、cutoffの既定値・指定値・境界値、切り抜きと半透明の深度、合成色とアルファ、
パーツの順序、両面の法線、負スケールのノード／スキニング／配置、Unlit、
一括描画と個別描画の一致、共有モデルの独立したアニメーションを検証します。

2026-09-09のReleaseビルドでは、Metal API Validationを無効にした既存の小三角形ベンチマークで、
1万個のOPAQUEモデルは個別描画1万回に対して一括描画1回でした。
50回の中央値は、描画命令の構築が個別2.226 ms／一括0.140 ms、GPU実行が0.140 ms／0.042 msです。
これはこの端末・小さなモデル・256×256の描画条件での測定値で、複雑なモデルの性能を示すものではありません。

## 互換性と今後の範囲

従来は全モデルをブレンド・両面で描いていました。
今回からGLBの既定値も反映するため、アルファ値だけ設定したOPAQUE素材は不透明になり、
`doubleSided` を指定していない板の裏側は消えます。
以前の見え方が必要なら、モデルにBLENDやdoubleSidedを明示してください。
描画時のアルファによるフェードは引き続き使えます。

ライブラリと同時に `shaders.metallib` も更新してください。
平行光源の影は[シャドウマップ](shadows-ja.md)に対応しています。
RGBの変更は[モデルのカスタムシェーダー](custom-shaders-ja.md)に対応しています。
[簡易ハイライト](highlights-ja.md)でモデル単位にツヤを加えられます。
金属度・粗さ、法線マップ、IBLは今後の対象です。
テクスチャは埋め込み画像／TEXCOORD_0／固定repeatに対応します。
読み込み時に[ミップマップ](mipmaps-ja.md)を生成し、linear＋mip linearで補間します。
MASKの細部はアルファの平均化により遠景で変化する場合があります。

仕様の参照先:
[glTF 2.0 Alpha Coverage / Double Sided](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#alpha-coverage)、
[KHR_materials_unlit](https://github.com/KhronosGroup/glTF/tree/main/extensions/2.0/Khronos/KHR_materials_unlit)。
