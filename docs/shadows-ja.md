# 平行光源とシャドウマップ

色を持つ平行光源1つと、正射影の深度マップ1枚による影を追加しました。
描画フレームごとに、光源から見た深度を先に描き、通常の描画で参照します。
ライブラリでは影は既定で無効です。ビューワーでは床と一緒に有効にしています。

## 設定

```cpp
alloy3d::DirectionalLight3D light;
light.direction = {-.35f, -.8f, -.45f}; // ワールド座標で光が進む向き
light.color = {1, .96f, .9f};
light.ambient = .25f;
light.diffuse = .75f;
ctx.SetDirectionalLight3D(light);

alloy3d::DirectionalShadow3D shadow;
shadow.enabled = true;
shadow.resolution = 1024;
shadow.bounds = {{-11, -.1f, -11}, {11, 8, 11}};
shadow.depthBias = .001f;
bool supported = ctx.SetDirectionalShadow3D(shadow);
```

- 光の方向は有限かつ非ゼロ。内部で正規化します。
- 色、ambient、diffuseは有限の0〜1。色は拡散光へ掛け、環境光は無彩色のままです。
- 不正な設定は `std::invalid_argument` で通知し、変更前の設定を保持します。
- 従来の `SetLight3D(direction, ambient, diffuse)` も使用できます。強度を0〜1へ丸め、
  無効な方向やほぼゼロの方向は以前の方向を保持します。設定済みの光源色は保持します。
- カスタムApplicationContextの既定実装は `SetDirectionalLight3D` を従来の
  `SetLight3D` へ渡すため、色の指定は反映しません。影の既定実装はfalseを返します。
  同梱のMetalホストは両方に対応し、有効・無効どちらの影設定もtrueを返します。

`bounds` は**影を落とす物体と受ける面の両方**を含むワールド座標の境界です。
その範囲を覆う光源の正射影を作ります。毎フレームのモデル走査や、カメラへの自動追従は行いません。
カメラを動かしても範囲は固定されます。広い範囲を指定するほど、同じ解像度での影は粗くなります。
範囲外の画素は影で暗くしません。実際の光源の視錐台は境界を覆う余白を含みます。

解像度は64〜4096、既定値1024の正方形です。2の累乗に限りません。
`depthBias` は光源の正規化された深度の差で、有限の0〜0.1、既定値0.001です。
自己遮蔽の縞が見えるときは少し増やせますが、大きすぎると影が物体から離れます。
光源側の描画では `slopeScale`（既定値2、有限の0〜8）による傾斜バイアスも併用します。
0で無効になり、最大の正規化深度オフセットは0.01に制限します。
有限で有効な境界、floatで表現できる投影が必要です。無効化するときも設定値は検証します。

## 影を落とすもの・受けるもの

| 描画対象 | 影を落とす | 影を受ける |
|---|---|---|
| OPAQUEモデル | する | ライティングが有効なら受ける |
| MASKモデル | cutoffを通った部分だけ | ライティングが有効なら受ける |
| BLENDモデル | しない | ライティングが有効なら受ける |
| 描画色のアルファが1未満のモデル | しない | ライティングが有効なら受ける |
| Unlitモデル | 不透明・切り抜きならする | 受けない |
| 三角形・面・箱・球などの基本図形 | アルファ1以上の部分 | 法線のある面が受ける |
| 線・3D文字・2D描画 | しない | 受けない |

影は拡散光だけを減らし、環境光は残します。深度比較サンプラーの線形フィルターで
境界を小さく平滑化します。透過色の付いた影や、半透明を積み重ねた影ではありません。
モデルの両面指定、負のスケール、スキニングは、通常描画と同じ頂点変換・面判定を使います。

通常描画で一括描画できるモデルは、影のパスでもパーツごとに一括描画します。
アニメーション姿勢は両パスで同じです。同じモデルへの描画登録ごとに姿勢を保存する機能はありません。
異なる姿勢の同時表示には `CreateModelInstance` を使います。

## 資源と実行順

深度マップは `Depth32Float` で、既存のフレーム管理に合わせて最大3ページを使います。
各ページは最初に影を描くときだけ確保し、同じ解像度なら再利用します。
インスタンスの変換データもフレーム内で一度だけ作り、深度パスと色パスで共有します。
GPUが使っている頂点・ジョイント・深度マップのページをCPU側で上書きしません。

解像度変更は安全に再利用できるページから反映します。
影を無効にした場合も、各ページの次の `beginFrame` で解放します。
通常は3フレームの描画で全ページが切り替わります。描画を休止したままなら解放が保留される場合があります。
`ReleaseUnusedMemory()` は有効な影のマップを保持し、通常の不要キャッシュ・バッファを解放します。

`GetRenderMemoryStats().shadowMapBytes` は深度テクセルの容量を合計した値です。
1024なら3ページで12 MiB、2048なら48 MiBです。影が無効な描画用の1テクセル（4バイト）も含みます。
物理的な割り当て粒度やドライバー領域を含むGPU使用量ではありません。
解放・サイズ変更待ちのページがあれば `releasePending` がtrueになります。

内部APIを直接使う場合は、描画の登録後、色のレンダーエンコーダーを作る前に
`encodeShadowMap:camera:` を同じコマンドバッファで呼びます。
続けて同じカメラ・姿勢で `render:camera:` を呼んでください。
深度パスを実行せず色パスだけ呼ぶ場合は影なしになります。
色パスを作れず `discardFrame` した場合も、実行済みの深度パスはGPU処理としてページを進めます。
同梱ホストはこの順序とフレーム同期を管理します。

## ビューワーと検証

**H** で影のON/OFFを比較できます。通常展示・Iのインスタンス展示・Mのマテリアル展示に共通です。
床は影を受け、MASKの格子は穴のある影を落とします。

`shadow_regression` はオフスクリーンのGPU画像で次を検証します。

- 基本図形・モデルの投影、影の外側、影の中に残る環境光、粗いマップでの自己遮蔽の抑制
- MASKの穴、BLEND／フェードの非投影、Unlitの非受影
- BLENDと通常モデルの受影、視点・投影を変更しても固定された影
- 負スケールのスキニング、一括描画と個別描画の一致
- アニメーションと共有モデルの独立性、光源色、設定エラー時の状態保持
- 3フレーム同時実行、解像度変更、色パスの破棄、無効化後の安全な解放

既存のマテリアル用GLBに加え、`animated_caster.glb` と `blend_lit.glb` を
`tools/generate_material_fixtures.py` から生成します。

今回は平行光源1つ・固定範囲のシャドウマップです。カスケードシャドウ、点光源の影、
広い範囲への自動追従、カスタムシェーダーAPIは含みません。
描画パスが増えるため、有効時のGPU負荷は物体数・頂点数・深度マップの解像度に依存します。
ライブラリ更新時には `shaders.metallib` も同時に更新してください。

参考: Appleの[深度比較サンプラー](https://developer.apple.com/documentation/metal/mtlsamplerdescriptor/comparefunction)と
[シャドウマップを使う描画サンプル](https://developer.apple.com/documentation/metal/rendering-a-scene-with-deferred-lighting-in-c%2B%2B)。
