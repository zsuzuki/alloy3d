# アニメーション更新の作業領域再利用

2026-09-09。比較元は `faa018b`。公開API、補間式、ループ処理、
ブレンドの境界動作を維持した内部実装の改善です。

## 変更内容

`NodeData` の名前・親子関係と、位置・回転・スケール・matrixを保持する
`PoseData` を分離しました。更新中に名前や子配列をコピーしません。
モデル読み込み時に、基準姿勢・2つの作業姿勢・ローカル行列・ワールド行列・
訪問フラグを確保し、その後の更新で再利用します。

ブレンドは1つ目の作業姿勢へ直接書き戻し、3つ目の姿勢コピーを撤廃しました。
各サンプリングでは基準姿勢から全成分を初期化するため、前のクリップで変更した
成分が次のクリップへ残りません。親子階層をたどる処理と補間関数は変更していません。

一時的な確保・解放を減らす代わりに、モデルの生存期間中は作業領域を保持します。
2つの姿勢配列は各ノード128 bytes×2、ローカル行列は64 bytes/ノード、
訪問フラグはvector<bool>で保持します。200関節モデル（204ノード）では、
この作業領域が約63.8 KiB＋訪問フラグです。これは構造体サイズによる概算で、
プロセス全体のメモリ削減量ではありません。既存のワールド行列はその場で更新します。

## 計測結果

Apple M3 Ultra / AppleClang 21 / Releaseで同じテストプログラムを比較元と修正後にリンク。
20回のウォームアップ後、200回の更新を15セット計測し、セットごとの
1更新当たり平均時間の中央値を記載しています。GPU描画・モデルロード・検証は
計測区間に含めず、メモリ確保回数は時間計測と別に200更新分を数えています。

| 関節数 | 更新 | 修正前 µs | 修正後 µs | C++確保回数/更新（前→後） |
| --- | --- | ---: | ---: | ---: |
| 25 | 通常再生 | 2.025 | 0.600 | 50 → 0 |
| 25 | ブレンド | 4.585 | 0.902 | 144 → 0 |
| 100 | 通常再生 | 6.696 | 1.999 | 185 → 0 |
| 100 | ブレンド | 16.617 | 3.133 | 549 → 0 |
| 200 | 通常再生 | 13.051 | 4.236 | 365 → 0 |
| 200 | ブレンド | 33.064 | 6.600 | 1,089 → 0 |

この条件では通常再生が約68〜70%、ブレンドが約80〜81%短縮しました。
実際のアプリのFPS改善率ではありません。生成モデルは長いノード名と5関節の
連鎖を持ち、旧実装の名前・子配列のコピーを含む条件です。
短い名前、深い階層、チャンネル数が異なるモデルにはそのまま当てはめられません。

確保回数は更新を実行するスレッドのC++ `new` / `new[]`（aligned版を含む）です。
Objective-C・Metal・直接のmalloc・他スレッドの確保数、RSSは測っていません。
性能計測ではMetal検証レイヤーとAddressSanitizerを無効にしています。

## テストモデルと検証

`assets/tests/animation` に25・100・200関節のGLBと説明を追加しました。
全て自作生成モデルで、Python標準ライブラリだけで再生成できます。
既存のスキンなしサンプルに加えて、実際に複数関節のウェイトを使う描画を検証します。

`animation_regression` は、生成モデルの構造から独立に計算した期待行列と比較します。
通常再生、クリップの往復切替、負の時刻、ループ、逆方向シーク、異なるクリップ長、
STEPとLINEAR、同一クリップの異なる時刻のブレンド、ブレンド率の0/1と範囲外、
アニメーションしないmatrix/TRSノード、不正なインデックスを確認します。
各モデル45姿勢について全ノードのワールド行列と3ページ分のスキニング行列を確認し、
さらに通常再生2種類とブレンドの3画像をGPUで描画します。

比較元で取得した全行列・画像と修正後の出力はバイト単位で一致しました。
ReleaseとDebug＋AddressSanitizerで、Metal検証レイヤー付きCTest全3件が成功しました。
今回の実機検証はGPU不在によるskipではありません。
比較キャプチャは作業用ディレクトリに保存し、OS/GPU依存の画像を固定期待値として
リポジトリには含めません。通常のCTestでは独立した期待行列、実際の描画の存在と変化、
定常更新でC++確保が0回であることを検証します。

## 再現手順

```sh
python3 tools/generate_animation_fixtures.py --check
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DALLOY3D_BUILD_TESTS=ON
cmake --build build -j 8
ctest --test-dir build --output-on-failure

# 検証レイヤーなしのCPU計測＋行列・描画検証
build/tests/alloy3d_animation_regression assets/tests/animation \
  build/shaders/shaders.metallib --require-no-alloc

# 比較元のライブラリに同じ検証ソースをリンクした実行ファイルで保存
path/to/baseline_animation_probe assets/tests/animation \
  path/to/shaders.metallib --record /tmp/animation-baseline

# 修正後で全行列と全ピクセルの一致を検証
build/tests/alloy3d_animation_regression assets/tests/animation \
  build/shaders/shaders.metallib --compare /tmp/animation-baseline
```

`--record` は各モデルの比較データと3姿勢のPNGプレビューを出力します。
バイナリの比較元を取り違えないよう、比較元のライブラリは修正前に別の場所へ保存します。
CTestはMetal GPUが利用できない場合に終了コード77でskipします。
