# 5km四方のストリーミング検証サンプル

森林・草地・2つの集落と、蛇行する川・2本の石橋・山道を含む5,000m × 5,000mの散策サンプルです。
家は窓枠・鎧戸・軒・玄関・煙突を備えた2種類。広葉樹と針葉樹、岩、草の共通モデルを配置します。
元モデルはPythonで生成し、生成画像の建材・葉・草・地面テクスチャを使用しています。
家・幹・岩の簡単な当たり判定、橋の歩行面と欄干、川への進入制限、急斜面の制限を備えます。
家の内部、ジャンプ・遊泳、NPC、セーブデータは未実装です。庭の柵は景観用です。

## 起動と操作

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DALLOY3D_BUILD_TESTS=ON -DALLOY3D_BUILD_OPEN_WORLD=ON
cmake --build build -j 8
open build/alloy3d_open_world.app
```

Python標準ライブラリだけでアセットをビルドディレクトリへ生成し、appへコピーします。
生成物は約246MiB。共有PNGの生成プロンプトと出典は `assets/samples/open_world/` に保存しています。
森林サンプルのメッシュ補助関数を利用しますが、元モデルは新規生成しています。
GLBの画像は同じディレクトリのPNGを外部bufferとして参照するため、GLBだけを移動しないでください。
画像のデコード・GPUテクスチャはライブラリの既存キャッシュで共有します。ライブラリだけのビルドでは
`ALLOY3D_BUILD_VIEWER/FOREST/OPEN_WORLD/TESTS` をOFFにすればPythonは不要です。

- WASD：移動（12m/s）。Shift：高速移動（100m/s）。矢印：視線。
- T：集落→橋→山道→もう一方の橋を往復する自動移動（100m/s）。R：村の入口へ戻る。
- M：全体図。北（−Z）が上、東（+X）が右の固定表示で、橙色の矢印は現在位置と視線方向です。
  色付き区画は詳細表示距離内の区画で、ロード完了状態とは別です。
- HUD：ロード済み区画・待機中・失敗・ロード/解放累計、モデル資源、描画メモリ、プロセスメモリ。

## データと描画

250m四方×20×20＝400区画。初期案の256mから、5kmに収まる250mへ調整しました。
`world.txt` はバージョンと世界サイズ、`N.cell` は共有アセットIDと配置、
`N.glb` は詳細地形、`N_far.glb` は地形・木・家をまとめた遠景モデルです。
5種類×2段階LODの共通モデルを共有し、84,105個の配置ごとにモデルをロードしません。
草は65m以内の周辺だけに決定的に配置し、50〜65mで背丈を下げて消します。
遠景の樹木は葉の透過テクスチャを使う交差カードに集約しています。全区画の遠景は常駐します。
橋・庭の柵・川・道路の共通モデルと、高さデータも常駐します。
川面の揺らぎと草の裏面の明るさは既存のモデルシェーダーAPIを使います。追加の描画パスはありません。
草と近景の樹木は既存の風表現を使用し、2x MSAAとalpha-to-coverageで葉の縁を整えます。

詳細地形・配置は600m以内を優先してロードし、800mを越えると解放します。
距離はカメラから区画AABBまでの水平距離です。詳細描画は450m以内かつロード済み、
未ロード区画は遠景モデルを維持します。地形は32×32/8×8分割と境界のスカートを使用。
読み込み粒度は250m、区画内の可視判定は62.5mのバケットで、木の張り出しも含めます。
木・家・岩は145mを境に2段階LODへ切り替えます。切替のポッピングは今後の調整対象です。

色の描画と影を独立に選び、近傍の画面外の物体も影の候補に残します。
ライト視錐台による追加カリングは `SetShadowCulling3D(true)` で有効化します。
既存アプリでは初期値OFF、従来の `SetFrustumCulling3D` の影への挙動は維持します。
インスタンスの配置行列は準備時に計算して、パーツごとの可視判定で再利用します。
カリング用の作業配列も容量を再利用し、`ReleaseUnusedMemory()` で解放できます。

## 地形と歩行

`heightfield.bin` は641×641頂点の高さと草の配置領域、`landscape.txt` は川・橋・散策経路です。
歩行時は、詳細地形と同じ三角形で高さを補間します。橋の上では分割した床面の高さを使い、
入口は地形生成時に合わせます。移動は最大1mのステップに分割して、Shift移動でも
川や建物をすり抜けにくくしています。障害物ではX/Z方向に分けたスライドを試みます。
建物・幹・岩の判定はロード済み詳細区画の配置を利用する簡易判定で、剛体物理ではありません。
自動移動は確認用の経路に直接追従します。通常のWASD移動には当たり判定が適用されます。

## 非同期ロードの責務

`ApplicationContext` はコールバック中だけ有効です。参照をスレッドに保存せず、
`CreateModelLoader()` でデバイスの寿命を保持するロード関数を取得します。
戻り値は独立したモデルのバックグラウンドロードに使用できますが、描画や
同じモデルのアニメーションを並行変更できるようになるAPIではありません。
非対応の独自コンテキストでは空の関数を返します。

`<alloy3d/streaming_cache.h>` の `StreamingCache<T>` はMetalに依存しない任意の補助機能です。
所有スレッドで優先順のキー配列を `Update()` に渡し、1つのワーカーでロードします。
サンプルでは待ち行列・実行中・完了待ちを合計4件以内に制限し、1フレームに1区画だけ
利用開始します。空間検索は10Hz、結果の反映は毎フレームです。

不要になった待機要求は削除し、実行中の要求が完了してもチケットが失効していれば
採用しません。同じキーが再要求されても古い完了結果は使いません。
ロード失敗は区画を一度要求範囲から外すまで保持し、再試行ループを防ぎます。
破棄時は実行中の1件を待ってワーカーを終了します。I/Oそのものの中断や
ハードな時間制限はなく、件数で反映量を制限しています。
アプリ終了経路では、描画停止後に `WillCloseWindow()` を呼び、ワーカーを停止してから
レンダラーを破棄します。

## メモリの見方と計測

`GetModelResourceStats(models)` は渡したモデル集合が参照するMetalバッファと
テクスチャをリソースの同一性で重複排除して集計します。モデル複製の共有分も
二重計上しません。CPUのモデル構造、テクスチャキャッシュだけが保持する資源、
ロード途中やGPU使用中の退役資源は含みません。GPU待ちは発生しません。

サンプルのプロセス値はmacOSの `phys_footprint`、ピークは0.5秒周期の観測最大値です。
モデル・描画メモリはその内訳と部分的に重なるため、プロセス値に加算しません。
厳密なバイト予算やテクスチャ圧縮の調整はこの段階では導入していません。

```sh
ALLOY3D_WORLD_TOUR=1 ALLOY3D_WORLD_FRAMES=1800 \
ALLOY3D_WORLD_CSV="$PWD/build/world-memory.csv" \
ALLOY3D_FRAME_PROFILE="$PWD/build/world-frames.csv" \
build/alloy3d_open_world.app/Contents/MacOS/alloy3d_open_world
```

`ALLOY3D_WORLD_ASSETS` でデータディレクトリを変更できます。
フレーム時間のCSVは既存の診断機能を使用します。性能計測ではMetal ValidationをOFF、
回帰テストではONとし、両者の結果を混同しないでください。

```sh
ctest --test-dir build --output-on-failure
build/tests/alloy3d_open_world_probe build/shaders/shaders.metallib \
  build/open-world-assets build/open-world-preview
build/tests/alloy3d_culling_probe build/shaders/shaders.metallib assets/samples/models/sample_mdl.glb
```

`streaming_regression` は要求数、重複ロード、解放、失敗、キャンセル・再要求競合を検証。
`open_world_navigation` は2本の橋の通行、欄干、川への高速移動、山道の勾配、建物の判定を検証。
`open_world_streaming` は実際のGLBを非同期ロードし、村・橋・森林・山・世界の端を含む2周で
ロード/解放、描画、同一地点のモデル資源量の安定を確認してCSVと画像を出力します。
`model_loader_lifetime` はコールバックとレンダラーの寿命を越えたロード、および
共有リソースの計上を実機で検証します。GPU不在の終了コード77は成功ではなくskipです。

## 景観更新後の実測（2026-09-27、Apple M3 Ultra、Release）

家・樹木・岩・草・川・橋・山道を追加した版です。

- 2560×1600、2x MSAA、散策経路を自動移動1,800フレーム（約30秒）。
  先頭60フレームを除くフレーム間隔の中央値16.667ms、p95 17.440ms、最大39.347ms。
  CPU更新の中央値0.480ms（p95 3.085ms）、描画命令登録0.728ms、GPU 0.908ms。
  遠景のLOD切替は残り、全地点の固定60FPSを保証する測定ではありません。
- 詳細区画は最大38/400、95ロード・59解放、ロード失敗0。
  モデルバッファ最大269.0MiB、共有テクスチャ25.7MiB。
  プロセスの観測最大1,127.4MiB（約1.10GiB）。
- 村・橋・森林・山頂・世界の端を巡る2周で、帰還地点のモデル資源は
  298,367,304 bytes（284.5MiB）で一致。プロセス全体の完全な無増加を意味しません。
- `streaming_regression`、`open_world_streaming`（Metal Validationあり）、
  `open_world_navigation` の3件が成功。橋2本の通行、欄干、川への高速移動、
  散策経路の水面・勾配、家の当たり判定を確認しました。
- ローカルの計測結果は `build/valley-results.json`、`valley-memory.csv`、`valley-frames.csv`。
  最終描画画像は `build/open-world-preview-0.ppm`〜`4.ppm`（村、橋、家、森林、山）です。

## 簡略モデル版の初回実測（2026-09-27、Apple M3 Ultra、Release）

- ウィンドウ2560×1600、1x MSAA、自動移動1,800フレーム（約30秒）。
  先頭60フレームを除くフレーム間隔の中央値16.666ms、p95 18.281ms、最大50.974ms。
  CPU更新の中央値0.230ms、描画命令登録0.419ms、GPU 0.392ms。
  最大遅延の原因は未特定で、固定60FPSの保証とはしません。
- 詳細区画は最大38/400、111ロード・78解放、ロード失敗0。
  観測最大のモデルバッファは191.1MiB、プロセスは878.9MiB。
  起動直後のモデル値は182.5MiB。遠景を全常駐させる構成の影響が大きいです。
- オフスクリーンで世界の端を含む同一経路を2周。帰還地点のモデル資源は
  197,773,432 bytes（188.6MiB）で一致。これはプロセス全体の完全な無増加を保証しません。
- 2万配置のカリング合成テストを変更前後で交互に3回実行。
  各回70フレームのCPU encode中央値は、変更前0.731/0.601/0.571ms、
  変更後0.586/0.442/0.439ms。3回の中央値同士では約26%短縮。
  画像ハッシュは全回 `11c349cbfdb20d2f` で一致し、GPUの改善は主張しません。
  これはCPUカリングの限定した比較で、アプリ全体のFPS改善率ではありません。
- 最初の全37 CTests成功後、ロードハンドルの寿命テストを追加し、変更に関係する
  8テストを再確認して成功（計38件を実行、GPU skipなし）。
  ストリーミングのCPU検証はASan/UBSanでも成功しました。

計測CSV・PNG/PPM・比較JSONは `build/` 内のローカル成果物です。
GPUカリング、永続インスタンスバッファ、静的頂点形式、GPU圧縮テクスチャ、
Metal Fast Resource Loadingは、この初回実装の計測結果を踏まえた後続候補です。
